# Ralph loops — v0.10 Codex-first trust pass

## Loop 1 — Use the provider the user wants first

**Finding:** Claude was implemented first, but the immediate dogfood target is Codex.

**Change:** Added a native Codex lifecycle adapter and project-local installer covering session, prompt, tool, permission, helper, stop, interrupt, and session-end events.

## Loop 2 — Respect Codex trust

**Finding:** Codex intentionally skips new or changed project hooks until the user reviews them.

**Change:** Setup now explicitly routes through `/hooks`. The Patch does not bypass or weaken Codex's trust review.

## Loop 3 — Prevent helper contamination

**Finding:** Codex tool inputs can include `agent_id` and `agent_type`; applying those events to the parent would violate the helper model.

**Change:** Subagent-scoped tool activity is ignored while `SubagentStart` and `SubagentStop` update the helper count.

## Loop 4 — Survive refresh and reordering

**Finding:** v0.9 lost the world after refresh and accepted late events that could rewind visible state.

**Change:** The bridge now retains an in-memory safe snapshot, replays it to reconnecting browsers, and rejects older session events.

## Loop 5 — Keep providers isolated

**Finding:** A raw session ID is not guaranteed to be unique across providers.

**Change:** Runtime identity is now `provider + sessionId`. Generic provider names receive calm, deterministic familiar names in bench order.

## Locked outcome

v0.10 is the first Codex-ready local checkpoint. It remains a dogfood prototype: no cloud account, remote phone access, productivity scoring, or external company-tool integrations.
