# Ralph loops — v0.6

Each loop asks whether a change improves the core promise: “In three seconds, can I tell whether my agents are okay and who needs me?”

## Loop 1 — First launch

**Finding:** A sleeping demo familiar made an unconfigured product look connected.

**Change:** The real empty state now says no agents are connected and offers two honest paths: connect an agent or try the four-agent scene.

**Rejected:** Automatically starting the demo. It would blur simulated and live data.

## Loop 2 — Trust

**Finding:** A familiar could look active long after the last received event.

**Change:** The inspector reports event freshness as updated just now, seconds/minutes ago, or quiet. Quiet does not claim the agent disconnected.

**Rejected:** Automatically changing quiet agents to disconnected. Silence is not proof that a coding agent stopped.

## Loop 3 — Connection

**Finding:** Setup documentation existed, but the application did not explain how the first familiar appears.

**Change:** Connect Agent is now available in the header and empty state. Its three-step guide distinguishes the included Claude adapter from the provider-neutral protocol.

**Rejected:** Provider account authorization in the prototype. Local lifecycle adapters remain the smaller, safer proof.

## Loop 4 — Long-running use

**Finding:** Four finished or ended sessions could permanently block later agents.

**Change:** When all benches are occupied, a new session may replace the oldest terminal session. Active work is never silently evicted.

**Rejected:** Replacing the least recently updated active session. A quiet session may still be doing valid work.

## Loop 5 — Comprehension

**Finding:** State, connection health, and freshness can be mistaken for one another.

**Change:** They remain separate concepts:

- bridge status says whether The Patch can receive events;
- lifecycle state says what the provider last reported;
- freshness says when that report arrived.

## Locked outcome

The prototype is an ambient supervisor, not an agent controller or productivity dashboard. The next proof is one real Claude Code session observed over a complete task.
