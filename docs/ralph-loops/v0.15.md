# v0.15 — taking the garnish off

The user's request (2026-09-25): remove the corner "camera" marks and the little
yellow dots on buttons, and clean the UI up so it stays game-like, easy and
familiar without so much custom CSS.

## Loop 1 — sort what does work from what is decoration

Every element in the chrome was asked one question: *does it tell you something,
or help you do something?*

| Element | Verdict |
| --- | --- |
| Corner ticks on the viewport | Decoration. Removed. |
| Brass nails on buttons, the state plate, the dialog, the drawer | Decoration, and they read as yellow dots, which is the colour of "needs you". Removed. |
| Iron straps and cedar post down the drawer's spine | Decoration. A 2px batten border does the same job. |
| Wood grain, worn highlight, knife-scored dividers | Decoration. They read as stripes and dashes. Plain hairlines instead. |
| Buttons and dialog hung at ±0.5° | Decoration, and it softened text edges. Removed. |
| Four different radii per corner | Decoration no one could see except as "slightly off". Three plain radii. |
| Status colours, glyph badges, portrait | Signals. Kept. |
| Dark plank-in-a-batten material | This is what the map's own placards are, so it is what makes the panel and map one object. Kept, as the only material. |
| Pressed-button lip, `kbd` keys | Familiar game affordances. Kept. |

## Loop 2 — the dots that were signals

- **The alert's pulsing gold dot** was a yellow dot on a button. It is now the
  same lit `!` badge a familiar wears on the map when it needs you, so the alert
  points at the creature it is about.
- **The Connect button's dot** was gold while half-installed and green once
  connected. Gold on a button that is not an alert competed with the alert. The
  dot now appears only when connected (green = live, the familiar convention);
  until then the button says so in words and gets a brass edge.
- **The trim bar beside the portrait** repeated the status chip. The portrait's
  frame now takes the state colour instead, the way a unit portrait does.

## Loop 3 — render and check

Screenshotted at 1512px (drawer open, alert shown, connect dialog) and 430px
(stacked sheet). Every surface reads as one material; the map placards, the
drawer, the buttons and the dialog are the same plank. No page errors.

## Rejected

- **Keeping the ticks as "the camera".** The reasoning was that a machine-made
  frame makes the rest read as hand-made. In practice they were four more marks
  on a busy picture.
- **A flat, borderless modern-web panel.** Too far the other way. The batten
  border and pressed lip are what keep it a game UI.
- **Replacing the brand square with a familiar sprite.** Adds art to the chrome;
  not asked for.

## Locked outcome

- One material, one button, three radii.
- A dot or a colour in the chrome is always a state.
- `tests/design-tokens.test.js` fails if tilt, nails, grain, straps, score
  lines, the worn highlight or viewport corner ticks come back.
