# Ralph loops — v0.9 Claude dogfood readiness

## Loop 1 — Setup friction

**Finding:** Manual file copying and JSON merging made the first real connection feel riskier than the product itself.

**Change:** Added one-command, project-local install, check, and removal. Installation is idempotent and preserves unrelated Claude settings and hooks.

## Loop 2 — Truthful completion

**Finding:** Claude's `Stop` event means a response ended, not that a task was completed.

**Change:** `Stop` remains **Waiting** at the Campfire. Only explicit `TaskCompleted` or `agent_completed` evidence unlocks **Finished** at the Shipping Dock.

## Loop 3 — Failure isolation

**Finding:** An ambient supervisor must never become a dependency of the coding agent.

**Change:** The adapter retains its short timeout and fail-open behavior. The installer writes only a local project configuration and provides a targeted uninstaller.

## Loop 4 — Debuggability

**Finding:** “It did not appear” needs a single diagnostic path rather than inspection across browser, server, and Claude configuration.

**Change:** Added `check:claude` and expanded bridge health with start time and last-event time. The UI now points directly to the check command.

## Loop 5 — Scope discipline

**Finding:** Additional species, integrations, or richer art would not answer whether the core visualization is useful with real work.

**Change:** The next gate is one complete Claude dogfood session. Provider two and production art remain deferred until that evidence exists.

## Locked outcome

v0.9 is a dogfood prototype, not a production integration. Its job is to make the first real Claude connection reversible, inspectable, privacy-minimal, and quick enough to test in 15 minutes.
